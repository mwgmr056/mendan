# 面談予約システム 設置手順

| ファイル | 置き場所 | 役割 |
|---|---|---|
| `Code.gs` | Google スプレッドシートの Apps Script | 予約データの保存、メール送信（API） |
| `index.html` | GitHub Pages | 利用者ページ（予約・変更・取り消し） |
| `admin.html` | GitHub Pages | 管理者ページ（枠の作成、予約状況、設定） |
| `config.js` | GitHub Pages | API の URL を書くファイル（上の2画面で共用） |
| `demo.js` | GitHub Pages | パソコン上で試すためのデモモード（本番では何もしません） |

## 0. まずパソコン上で試す（デモモード）
Google も GitHub も使わずに、全機能を何度でも試せます。

1. 6つのファイル（`index.html`・`admin.html`・`config.js`・`demo.js`・`Code.gs`・`README.md`）を**同じフォルダ**に置く
2. `config.js` は `window.API_URL = 'demo';` のまま
3. `admin.html` を **Chrome か Edge** で開く（ダブルクリック）→ パスワード `demo1234` でログイン
4. 枠を作り、「利用者に送るURL」の `index.html` を開いて予約してみる
5. 送られるはずのメールは、画面右下の「📧 送信メール」で文面と変更リンクを確認できます（リンクをクリックすると変更画面が開きます）
6. やり直したいときは「送信メール」パネルの「デモデータを全消去」

- データはそのブラウザの中だけに保存されます（他の人とは共有されません）
- 画面の文言やデザインを直したら、ファイルを保存してブラウザを再読み込みするだけで反映されます
- `Code.gs` を直した場合も、デモモードならそのまま反映されます（本番では再デプロイが必要）

## 0-2. パソコン上のファイルのまま、本物の Google と接続して試す
下の手順1を済ませたあと、`config.js` の `'demo'` を Apps Script の URL に書き換えて `admin.html` を開きます。実際にメールが届くか、ここで確認できます。
GitHub に公開したあと管理者ページを開くと、メールの変更リンクは公開URLに自動で切り替わります。

## 1. Apps Script を準備する
1. Google ドライブで新しいスプレッドシートを作成
2. メニュー「拡張機能 → Apps Script」を開き、`Code.gs` の中身を丸ごと貼り付ける
3. 冒頭の `CONFIG.ADMIN_PASSWORD` を、推測されにくい8文字以上のパスワードに変更して保存
4. 関数一覧から `setup` を選んで「実行」→ 権限の承認画面で許可
   （「このアプリは確認されていません」と出たら「詳細 → 安全ではないページに移動」で進めます。ご自身のスクリプトなので問題ありません）
5. 右上「デプロイ → 新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行ユーザー：**自分**
   - アクセスできるユーザー：**全員**
6. 表示された URL（`https://script.google.com/macros/s/…/exec`）をコピー

※ 以後 Code.gs を修正したときは「デプロイを管理 → 鉛筆アイコン → バージョン：新バージョン → デプロイ」で反映します（URL は変わりません）。

## 2. GitHub Pages に画面を置く
1. `config.js` の `API_URL` を手順1-6の URL に書き換える
2. GitHub で新しいリポジトリを作り、`index.html`・`admin.html`・`config.js`・`demo.js` の4つをアップロード
   （`Code.gs` は Apps Script 側に置くものなので、GitHub には載せません。demo.js は本番では何もしません）
3. リポジトリの「Settings → Pages」で Branch を `main` / `/(root)` にして保存
4. 数分後、次の URL で開けます
   - 管理者ページ：`https://ユーザー名.github.io/リポジトリ名/admin.html`
   - 利用者ページ：`https://ユーザー名.github.io/リポジトリ名/`
   - リポジトリ名は短いもの（例：`mendan`）にすると、利用者に送る URL も短くなります

## 3. 使い方（管理者）
1. 管理者ページを開き、パスワードでログイン
2. **設定**タブで、面談名・案内文を入力して保存
   （利用者ページの URL は、GitHub 上の管理者ページを開いたときに自動で決まります。設定は不要です）
3. **枠の作成**タブで、日付ごとの開始・終了時刻と、共通の面談時間・休憩時間を入れる
   （日付ごとに時間帯を変えられます。同じ日付を2行入れれば午前・午後のように分けられます）
   → プレビューで枠を確認して「枠を作成」
   例：9:00〜12:00、面談30分、休憩10分 → 9:00 / 9:40 / 10:20 / 11:00 の4枠
4. **予約状況**タブの「利用者に送るURL」をコピーして、利用者へ一斉送信
5. 予約状況タブで、どの枠に誰が入っているかを確認します
   - 空き枠の削除、予約の取り消し（本人への通知の有無を選択可）、CSV出力ができます

## 4. 利用者側の流れ
1. URL を開き、空いている枠を選んで氏名・メールアドレスを入力
2. 確定メールが届きます。メールに**本人専用の変更リンク**が入っています
3. そのリンクを開くと、別の枠への変更や取り消しができます（変更・取り消しのたびにメールが届きます）
4. メールをなくした人は、利用者ページ下部の「すでに予約した方」から変更リンクを再送できます

## 仕様メモ
- **先着順**：同じ枠に同時に申し込みがあっても、ロック処理で先着1名だけが確保できます。後の人には「先に埋まりました」と表示されます
- **重複予約**：同じメールアドレスで予約できるのは1枠まで（`ONE_PER_EMAIL` で変更可）
- **締切**：開始時刻を過ぎた枠は一覧から消え、その予約は変更・取り消しもできなくなります
- **データ**：スプレッドシートの「予約枠」シートに保存されます。直接見たり編集したりしても構いません（列の順番は変えないでください）
- **メール上限**：Google の1日の送信上限があります（個人アカウントで約100通/日、Workspace で約1,500通/日）
- **返信先**：利用者が確定メールに返信すると、Apps Script を設置した Google アカウントに届きます
- **セキュリティ**：管理者ページの URL は公開されますが、パスワードがないと何も見られません。他の利用者の氏名やメールは利用者ページからは見えません
- 氏名・メールアドレスは Google スプレッドシートに保存されます。学内の個人情報の取り扱いルールに沿っているかご確認ください
